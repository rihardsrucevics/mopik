## 2. Rider's rules added in this stretch (in addition to CLAUDE.md's)

- Every map button is always visible; a button with no logic in the current state is shown disabled (grey), never hidden.
- Controls keep stable slots; nothing appears or disappears so that others jump.
- A guidance line always says **what is happening – what to do**; never a state without an exit and a line; a line may not promise an option that is not on screen.
- Never a generic „neizdevās savienot”: an edit ends in a proposal, a warned proposal, or a named blocker with a fix.
- Pass-through points are not listed in the form. „+” adds pass-through points; the field (search) is for stops.
- Latvian: never „piesit”; en dashes „–”, not em dashes „—”; product page named „Par Mopiku” in Latvian, „About …” pattern in the others.
- Gates keep the 🚪-style map marker (now own SVG); map badges otherwise stay ⚠️ and 🔥 only.
- No alcohol/tobacco, no drag-and-drop reordering on phones (unchanged).

## 3. How we worked (and what changed)

- Rider wants subagents doing the code and me directing; every piece in its own git worktree from `main`, one commit set per piece.
- **Small releases, no new items to a running agent, full suite only before big releases.** At most about two browser-test agents at once (three pushed the 8-core machine to load 12–25 and made everything slow).
- Ship flow: push a branch, open a PR, merge it myself when Vercel and my checks are green (rider is at his computer); Vercel deploys `main` automatically. On the phone the rider merges the PR himself. The permission classifier blocks me from pushing to `main` directly; PR merge works.
- Every agent must run the fast kit (`scripts/verify/smoke.sh`); the router recordings are git-ignored and stale after any routing-code change (`RECORD=1` refreshes them, about 3 minutes).
- Agents sometimes stall (10 minute watchdog) or lose network; resume them with `SendMessage`, and always check the worktree state first.
