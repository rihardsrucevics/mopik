# LVM GEO for Mopik — should we use it alongside OSM? (2026-09-12)

Research by an Opus subagent; scripts in `scripts/lvm/` (`fetch.ts`, `gap.ts`,
`fetch-equipment.ts`), fetched samples in `data/lvm/`.

**Verdict: do NOT ingest LVM forest roads into routing. OSM already has 99.9 %
of them, with better tags. Worth taking: the gates/barriers layer, an optional
map overlay, and a fire-season advisory. ~1 day.**

## 1. The data

**Open data portal (the real source):** data.gov.lv, publisher AS "Latvijas
valsts meži", 9 datasets. Metadata:
`https://data.gov.lv/dati/lv/api/3/action/package_show?id=as-latvijas-valsts-mezi-mezsaimniecibas-infrastruktura`

- Forest infrastructure: https://data.gov.lv/dati/lv/dataset/as-latvijas-valsts-mezi-mezsaimniecibas-infrastruktura
- Forestry / fire protection: https://data.gov.lv/dati/lv/dataset/as-latvijas-valsts-mezi-mezkopiba-un-ugunsapsardziba
- Weekly updates, zipped SHP, LKS-92 / EPSG:3059. Reproject with
  `ogr2ogr -t_srs EPSG:4326 out.geojson in.shp`.
- The SHP download URLs on the portal are all HTTP 404 today
  (`https://lvmgeo.lvm.lv/PublicData/SHP/*.zip`); the `.docx` field specs work.

**WMS services (what works):** https://www.lvmgeo.lv/dati/tabmenu-two/brivpieejas-wms-wfs-servisi

| service | URL |
|---|---|
| raster WMS | `https://geoserver.lvmgeo.lv/wms62531a9bfcfa4015856924e94076a178?` |
| WMTS | `https://geoserver.lvmgeo.lv/wmts8699a6fe9bb543bcbf4e463a88bf9049?` |
| vector WMS | `https://geoserver.lvmgeo.lv/wmsvector62531a9bfcfa4015856924e94076a179?` |

There is **no public WFS**: the gateway whitelists only `GetMap`,
`GetCapabilities`, `GetLegendGraphic`. Vector data is still obtainable: GetMap
accepts `FORMAT=application/json;type=geojson` and returns GeoJSON (WGS84 via
`CRS:84`), generalised per output resolution — tile at 4096 px (~0.3 m/px).

Layers (`LVM_Meza_infrastruktura`, `LVM_Mezkopibas_dati`):

| layer | title | geom | MaxScaleDenom |
|---|---|---|---|
| `road` | Meža ceļi (LVM) | line | 1 001 000 |
| `planedroads` | Attīstāmie meža ceļi | line | — |
| `roadequipment` | Autoceļu aprīkojums — gates/barriers | point | 25 100 |
| `bridge` | Tilti un lielās caurtekas | point | 250 100 |
| `firebreak` | Meža stigas (quarter lines) | line | 250 100 |
| `fireline` | Mineralizētās joslas | line | — |
| `culvert`, `roadloop`, `roaddescent`, `passingplace` | culverts, turning/passing places | point | — |

`roadequipment` is empty above 1:25 100 — tile below that scale.

**Attributes — the critical finding.** `road` has only `roadname`,
`lvm_district_code`, `ogc_fid`, `SHAPE_LEN`. **No road class, surface,
condition, width or access.** `roadequipment.equipmentsubtype`: 1 Ceļazīme,
2 LVM informatīvā zīme, **3 Barjera, 4 Vārti**, 5 Signālstabiņi (~9200
objects nationally). No layer for closures or fire-period restrictions.

## 2. Licence

data.gov.lv: `"license_id": "CC0-1.0"` for both datasets — public domain:
derived data, redistribution, commercial and web-service use permitted, no
attribution required (still good manners; required if it ever went into OSM).

Tile services: LVM GEO says "AS "Latvijas valsts meži" ikvienam interesentam
piedāvā izmantot brīvpieejas WMS un WFS servisus" and invites use "izglītības,
izpētes, zinātnes un kvalitatīvu ģeotelpisku lietotņu un informācijas sistēmu
izstrādes vajadzībām". GetCapabilities: `<Fees>NONE</Fees>`,
`<AccessConstraints>NONE</AccessConstraints>`. Embedding is permitted in
substance; commercial use of the *tile service* is not spelled out — for a
commercial Mopik prefer the CC0 data or ask lvmgeo@lvm.lv.

## 3. The gap vs OSM — measured

~10×10 km boxes; LVM from the vector WMS, OSM via Overpass. Sampled every
25 m, "near" = 15 m. Re-verified with shapely/pyproj in EPSG:3059.

```
area        LVM feats   LVM km   missing   miss %   OSM trk km  trk not LVM
---------------------------------------------------------------------------
baldone            20     40.5      0.03      0.1%       362.2        319.7
turaida             0      0.0      0.00        —        333.3        333.3
kemeri_tukums       —      2.8      0.05      1.7%           —            —
ogre_madliena       —     49.8      0.19      0.4%           —            —
```

Baldone: OSM is missing 30 metres out of 40.5 km. OSM calls those roads
`unclassified` 40.0 km / `track` 2.3 km, surface `gravel` 34.2 km,
`fine_gravel` 5.0, `compacted` 0.7. OSM has the geometry *and* better
attributes than LVM ships. Turaida/Sigulda: LVM owns no forest roads in the
box at all (nearest LVM road 6.3 km away). 320 km of OSM track/path/unclassified
in the Baldone box is not LVM road — the rider's network is overwhelmingly
non-LVM and already in OSM.

**Gates — the one genuine gap.** Baldone: 34 equipment points, 4 Barjera; the
nearest OSM `barrier=*` node to each is 2.2–5.2 km away — none is in OSM.
OSM also carries no `access`/`motor_vehicle` tag on those 40 km.

## 4. Integration options

**(a) MapLibre overlay (~2 h).** Raster source next to the TET overlay:

```
https://geoserver.lvmgeo.lv/wmsvector62531a9bfcfa4015856924e94076a179?SERVICE=WMS&VERSION=1.1.1&REQUEST=GetMap&LAYERS=road&STYLES=&SRS=EPSG:3857&BBOX={bbox-epsg-3857}&WIDTH=512&HEIGHT=512&FORMAT=image/png&TRANSPARENT=true
```

`tileSize: 512`, hidden above 1:1 001 000. Attribution "© LVM GEO (CC0)".

**(b) Routing enrichment — don't.** 0.1–1.7 % new geometry does not justify a
PBF merge, snapping and a segment rebuild. If ever: `ogr2ogr` → OSM XML
(`highway=track`, `surface=gravel`, `source=LVM GEO`), snap endpoints within
~20 m to OSM junctions, `osmium merge` (osmium not installed; `brew install
osmium-tool`).

**(c) Fire season as a UI warning (~3 h).** No API or feed (VMD checked).
Hardcode the season, show an advisory; VMD declares it annually, typically
from late April / 1 May: https://www.vmd.gov.lv/lv/ugunsdrosiba-meza.

**(d) Legal.** Meža likums 5. pants: vehicles only "pa ceļiem un dabiskām
brauktuvēm" (https://likumi.lv/ta/id/2825-meza-likums). MK noteikumi Nr. 238
"Ugunsdrošības noteikumi" 423.6.: during the fire period it is forbidden
"braukt ar mehāniskajiem transportlīdzekļiem pa mežu un purviem ārpus ceļiem"
— roads themselves stay legal; 412.: VMD sets the period each year
(https://likumi.lv/ta/id/281646-ugunsdrosibas-noteikumi). The legal line is
road vs off-road, not LVM vs non-LVM; bare `highway=path` in a forest during
the fire period is the risky case, governed by `accessPolicy`.

## 5. Recommendation

1. Import `roadequipment` barriers/gates (subtype 3, 4) → map pins + "gates on
   route" warning (~4 h). The only dataset adding information OSM lacks.
2. Optional LVM roads WMS overlay behind a toggle (~2 h).
3. Fire-season advisory, hardcoded dates, quoting 423.6 (~3 h).
4. Do not merge LVM roads into the OSM PBF: measured 0.1 % benefit.

Could not verify: bulk SHP downloads (404), commercial intent of the tile
service, national gate density (extrapolated from Baldone), `firebreak` /
`planedroads` not measured.
